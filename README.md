# سامانه مدیریت و اتوماسیون درخواست‌ها

سامانه‌ای تحت وب برای **ثبت، پیگیری و تأیید سلسله‌مراتبی درخواست‌های فنی**؛ مانند انتقال فایل، پشتیبان‌گیری، پیگیری نامه، بازکردن VDI و راه‌اندازی مجدد سرور. هدف پروژه جایگزین‌کردن فرایند سنتی و کاغذی/نامه‌محور درخواست‌ها با یک گردش‌کار الکترونیکی، شفاف و قابل ردگیری است.

## معرفی

در این سامانه هر فرد بر اساس نقش خود حساب کاربری دارد. کاربران به دو گروه کلی تقسیم می‌شوند:

| گروه | توضیح |
|------|-------|
| **درخواست‌کننده‌ها** | درخواست خود را ثبت می‌کنند و وضعیت آن را پیگیری می‌کنند. هر درخواست‌کننده فقط به نوع یا انواع مشخصی از درخواست‌ها دسترسی دارد. |
| **تأییدکننده‌ها** | به‌صورت سلسله‌مراتبی درخواست‌ها را بررسی می‌کنند و تأیید، رد یا (در مرحله پایانی) اجرا می‌کنند. |

## قابلیت‌های اصلی

- **گردش‌کار تأیید چندمرحله‌ای** با ثبت تاریخچه کامل هر تأیید یا رد (نام تأییدکننده، تاریخ، توضیحات و دلیل رد)
- **پشتیبانی از ۹ نوع درخواست** با فرم‌های اختصاصی برای هر نوع
- **انتقال فایل داخلی**؛ کاربر خودش پس از تأیید مدیر/معاون فایل را منتقل می‌کند و نیازی به پشتیبان شبکه نیست
- **شناسنامه سامانه‌ها**؛ ثبت مشخصات سامانه‌ها و سرورها و انتخاب آن‌ها هنگام ثبت درخواست
- **اصلاح و ثبت مجدد درخواست ردشده** همراه با نگهداری تاریخچه نسخه‌های قبلی و شمارنده اصلاح
- **لغو درخواست** توسط درخواست‌کننده
- **تأیید خودکار** در برخی درخواست‌ها (مانند پیگیری نامه برای رئیس واحد / مدیر کل)
- **تقویم شمسی** با انتخابگر تاریخ فارسی و رابط کاربری راست‌به‌چپ (RTL) با فونت وزیرمتن
- **اعلان‌ها** از طریق Toast و Service Worker
- **احراز هویت امن** با کوکی HttpOnly و ذخیره رمز عبور به‌صورت هش‌شده (bcrypt)
- امکان تغییر رمز عبور، ثبت‌نام و مشاهده تاریخچه هر درخواست

## نقش‌ها و سلسله‌مراتب تأیید

| نقش | عنوان در سامانه | وظیفه |
|-----|-----------------|-------|
| `REQUESTER` | درخواست‌کننده | ثبت درخواست |
| `V_REQUESTER` | درخواست‌دهنده ویدئو کنفرانس | فقط ثبت درخواست ویدئو کنفرانس |
| `GROUP_LEAD` | رئیس واحد | تأیید مرحله اول |
| `DEPUTY` | مدیر کل / معاون | تأیید مرحله دوم |
| `NETWORK_HEAD` | واحد شبکه و امنیت | بررسی و تأیید فنی |
| `NETWORK_ADMIN` | پشتیبانی شبکه | اجرای نهایی درخواست |
| `NETWORK_USB_ADMIN` | پشتیبانی USB | رسیدگی به درخواست‌های پورت USB |
| `VC_ACCEPTER` | تأییدکننده ویدئو کنفرانس | تأیید ویدئو کنفرانس و تعیین شماره اتاق |

مسیر پیش‌فرض تأیید:

```mermaid
flowchart LR
    A[درخواست‌کننده] --> B[رئیس واحد]
    B --> C[مدیر کل / معاون]
    C --> D[واحد شبکه و امنیت]
    D --> E[پشتیبانی شبکه]
    E --> F((انجام شده))
```

هر درخواست در یکی از وضعیت‌های زیر قرار دارد: **در حال بررسی** (`PENDING`)، **تأیید شده** (`APPROVED`)، **رد شده** (`REJECTED`)، **انجام شده** (`COMPLETED`) و **لغو شده** (`CANCELLED`).

## انواع درخواست

| نوع | توضیح | فیلدهای اصلی |
|-----|-------|--------------|
| انتقال فایل | انتقال فایل بین سرورها، عادی یا داخلی | مبدأ و مقصد (IP و مسیر)، نام و قالب فایل، گیرنده، شماره نامه |
| پشتیبان‌گیری | درخواست بکاپ از سرور | IP سرور، روش (کامل / افزایشی)، مسیر ذخیره، زمان‌بندی، مدت نگهداری |
| بازکردن VDI | دسترسی VDI و انتقال داده | نوع رسانه، نام فایل یا پوشه، آدرس مبدأ و مقصد، نام سرور یا سیستم، پورت |
| نوار (Tape) | انتقال روی نوار | IP سرور، نام و مسیر فایل |
| پورت USB | فعال‌سازی موقت پورت USB | IP سرور، مدت زمان |
| نصب برنامه | نصب نرم‌افزار روی سرور | IP سرور، نام برنامه یا لینک |
| ویدئو کنفرانس | رزرو جلسه | تاریخ، ساعت شروع و پایان، تعداد شرکت‌کنندگان |
| راه‌اندازی مجدد سرور | ری‌استارت زمان‌بندی‌شده یا فوری | IP سرور، زمان، فوری‌بودن، توضیحات (حداکثر ۱۰۰ کاراکتر) |
| پیگیری نامه | پیگیری نامه ارسال‌شده از سامانه دیگر | شماره نامه، موضوع، توضیحات |

موضوع‌های قابل انتخاب در **پیگیری نامه**: سرور جدید، ایجاد VDI، دسترسی VDI، حذف سرور، حذف دسترسی VDI، افزایش/کاهش منابع و ایجاد تانل.

## انتقال فایل داخلی

در روش سنتی، انتقال فایل توسط پشتیبان شبکه انجام می‌شد. در حالت **انتقال داخلی** (انتقال بین سرورهای یک سامانه) این فرایند ساده‌تر شده است:

1. کاربر درخواست انتقال فایل را با گزینه «انتقال داخلی» ثبت می‌کند و فایل را در سامانه بارگذاری می‌کند.
2. نام و قالب فایل به‌صورت خودکار از فایل بارگذاری‌شده استخراج می‌شود و نیازی به وارد کردن مسیر مبدأ و مقصد نیست.
3. درخواست پس از تأیید **رئیس واحد و مدیر کل / معاون** آماده اجرا می‌شود.
4. خود کاربر انتقال را انجام می‌دهد و پشتیبان شبکه درگیر نمی‌شود.

فایل‌های بارگذاری‌شده تاریخ انقضا دارند و وضعیت دانلودشدن آن‌ها ثبت می‌شود.

## شناسنامه سامانه‌ها

هر کاربر می‌تواند مشخصات سامانه‌ها و سرورهایی را که با آن‌ها کار می‌کند ثبت کند. هنگام ثبت درخواست، انتخاب سامانه از شناسنامه الزامی است و مشخصات آن به درخواست پیوست می‌شود.

**سامانه (Contractor)**
- نام سامانه و نام پیمانکار
- حداکثر سه نماینده پیمانکار با شماره تماس
- کاربران مجاز به ثبت درخواست برای آن سامانه
- ثبت‌کننده و واحد ثبت‌کننده

**سرور**
- آدرس IP (اجباری) و نام VM
- آدرس DNS و URL
- ادارات مرتبط
- نوع کاربری سرور (بکاپ، دیتابیس و ...)
- مسئول پشتیبان‌گیری و دوره پشتیبان‌گیری

## فناوری‌های استفاده‌شده

| بخش | ابزار |
|-----|-------|
| فرانت‌اند | React 19، TypeScript، Vite 6 |
| استایل | Tailwind CSS 4، فونت وزیرمتن |
| تقویم شمسی | react-multi-date-picker |
| بک‌اند | Node.js، Express 4 (اجرا با `tsx`) |
| پایگاه داده | PostgreSQL (با ستون‌های JSONB برای جزئیات درخواست‌ها) |
| احراز هویت | bcryptjs، cookie-parser (کوکی HttpOnly) |
| بارگذاری فایل | multer |
| فایل‌های Excel | xlsx |

## ساختار پروژه

```
├── server/                  # بک‌اند (Express)
│   ├── index.ts             # نقطه ورود و API
│   ├── seed.ts              # داده‌های اولیه
│   └── check-db.ts          # بررسی اتصال و وضعیت دیتابیس
├── auth/AuthContext.tsx     # مدیریت نشست کاربر
├── pages/                   # صفحات ورود، ثبت‌نام و برنامه اصلی
├── components/              # فرم‌ها، لیست‌ها، تاریخچه، تأیید و ...
├── layouts/                 # قالب صفحات احراز هویت
├── hooks/                   # هوک‌های اعلان و Toast
├── utils/                   # سرویس API و اعلان‌ها
├── public/sw.js             # Service Worker
├── constants.ts             # نقش‌ها، سلسله‌مراتب و برچسب‌ها
└── types.ts                 # تایپ‌های مشترک
```

## راه‌اندازی

### پیش‌نیازها

- Node.js نسخه ۱۸ یا بالاتر
- PostgreSQL نسخه ۱۲ یا بالاتر

### مراحل

```bash
# ۱. نصب وابستگی‌ها
npm install

# ۲. ساخت فایل .env (نمونه در ادامه)

# ۳. بررسی اتصال دیتابیس و ایجاد داده‌های اولیه
npm run check-db
npm run seed

# ۴. اجرای بک‌اند (ترمینال اول)
npm run server

# ۵. اجرای فرانت‌اند (ترمینال دوم)
npm run dev
```

### متغیرهای محیطی

```env
DB_USER=postgres
DB_PASSWORD=<your-password>
DB_HOST=localhost
DB_PORT=5432
DB_NAME=<database-name>
PORT=5000
FRONTEND_URL=http://localhost:3000
NODE_ENV=development
```

### دستورهای npm

| دستور | کاربرد |
|-------|--------|
| `npm run dev` | اجرای فرانت‌اند در حالت توسعه |
| `npm run build` | ساخت نسخه production فرانت‌اند |
| `npm run preview` | پیش‌نمایش نسخه ساخته‌شده |
| `npm run server` | اجرای بک‌اند با بارگذاری مجدد خودکار |
| `npm run server:prod` | اجرای بک‌اند در حالت production |
| `npm run seed` | ایجاد داده‌های اولیه |
| `npm run check-db` | بررسی دیتابیس |

## استقرار

- مقدار `NODE_ENV=production` را تنظیم کنید.
- برای فعال‌بودن کوکی‌های `secure` باید سامانه پشت HTTPS اجرا شود.
- بک‌اند Node.js قابل استقرار روی IIS با ماژول **iisnode** است و فایل‌های استاتیک ساخته‌شده توسط Vite را می‌توان از همان سرور ارائه کرد.
- پیش از استقرار، رمزهای پیش‌فرض کاربران نمونه را تغییر دهید.
